# Decision: the Binance Agent OS Mini Hackathon is out of scope for this document, open at submission level

Recorded 2026-09-05 by `12-BINANCE.md`. Filed so the pointer in section 6 and open question 12 resolves
to something rather than to an empty folder.

## The fork

The Mini Hackathon closes **2026-09-08 23:59 UTC**, one day before the main build closes on 2026-09-09.
Its pool is 60,000 USDC, with Track A the build track at 20,000 USDC and no published rubric beyond
"the best agent built with Agent OS" (`R17-binance-agent-os.md`). A marketplace that hires over B402 and
lists into Bazaar is, on its face, an agent built with Agent OS, so the overlap is real rather than a
stretch.

Two constraints bear on it and neither resolves it:

- The Mini Hackathon's own rules say **nothing either way** about entering a project that is also
  entered elsewhere. Not prohibited, not permitted (`R17-binance-agent-os.md`).
- The main track allows **one entry per team**. That binds the main side rather than this one, so it
  does not forbid a second programme by itself.

## What is decided

**Nothing in `12-BINANCE.md` changes with the answer.** Every Binance surface in that document is
chosen on its own grounds: the B402 client behind our `facilitator` interface, the Bazaar read, the BABT
leg of E3, the wallet connector, the refusal of market data. Entering or skipping the Mini Hackathon
adds no integration, removes none and changes no state in its section 8 table. So the technical work is
not blocked and does not wait on this.

**The decision itself is a submission-level call.** It expires on 2026-09-08 when the programme closes.
After that date this file is history rather than an open item.

## Rejected

Deciding it here, either way, inside a Binance-integration document. Rejected because the inputs are
programme eligibility plus how many entries to file, which is not a property of any Binance surface. A
technical document that quietly commits an entry also hides the commitment from whoever tracks entries.
The opportunity tracker is where an entry is recorded, not a design file.

Also rejected: treating the silence in the Mini Hackathon rules as permission. Absence of a prohibition
is not a grant, which is the same posture the licensing rule takes on absent terms. If the answer
matters before 2026-09-08 the route is asking the programme rather than inferring.
