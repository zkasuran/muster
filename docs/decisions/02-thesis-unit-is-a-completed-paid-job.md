# Decision: the unit of the marketplace is a completed paid job

Recorded by `02-THESIS.md` sections 1 and 4. This is the choice the rest of the product follows from.

## The decision

Every surface, every count and every ranking input is built on a settled paid job rather than on a
listing or a probe. A listing is a claim. A job is a fact. The headline number is **settled turnover
per category over a stated window**, with the agent count beside it as the denominator and its block
height attached.

## The alternative rejected

Reachability as the unit: an agent that answers a probe is listed and counted. Also rejected: leading
with the agent count, which is what a directory does.

## Why

Probing appears in at least eight independent rival builds and it proves a web server rather than a
service. The rubric's journey ends at "activate it" and a paid job with a receipt is the only signal
on BSC today that cost somebody money to create. It is also the only artifact that answers Data
Quality's ask for enough to make a genuinely informed call.

The agent count is the denominator behind the discoverability problem BNB Chain's own brief names,
not an achievement. Turnover reframes the product from a directory into a market.

Consequences that are structural rather than presentational:

* A shelf row means somebody paid this agent for this category of work, with the receipt attached.
* The score consumes settled jobs only. Raw ERC-8004 feedback is displayed with its author and never
  treated as a score, because 111 addresses wrote all 29,712 of them.
* A receipt is a first-class page: content hash, hash rule, transaction, block, pinned block, inputs
  hash, code version plus the command that reproduces the hash.
* Every payment carries an `origin` tag of exactly `house` or `order`, checked at ledger append time.
  Revenue and volume count `order` only.

The cost is taken deliberately. A paid-job unit makes the shelves small, where a reachability unit
would render hundreds of rows per category today. Small and true beats large and unusable and the
large set stays visible as the candidate list.

## What it binds

`02-THESIS.md`'s hireable bar, `06-QUALITY.md`'s score, `07-MATCHING.md`'s ranking, `08-MONEY.md`'s
ledger invariant, `03-TAXONOMY.md`'s shelf counts, `13-PARTNERS.md`'s report.

## What would make us revisit it

Nothing inside this programme. Volume changes the tuning, not the unit: once categories carry counted
medians the same unit supports the statistics that are unavailable at launch.
